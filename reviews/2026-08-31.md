# Code review — 2026-08-31

Scope: all implemented application code except `src/renderer/**`. Missing work from `docs/SPEC.md` is intentionally excluded. Findings are ordered by severity and are written as implementation instructions for a follow-up agent.

## P0 — Undo can silently mark disk-divergent content as saved

**Evidence:** `Tab` stores complete `Document` values in its undo/redo stacks (`src/tabs.rs:14-17`). `Document` includes the persistence-only `dirty` flag. `Tabs::undo` and `Tabs::redo` replace the current document wholesale with one of those snapshots (`src/tabs.rs:427-445`). Saving clears the live document's flag, but it does not rewrite historical snapshots.

**Failure sequence:** open a clean note, edit it, save it, then undo. The undo snapshot predates the edit and carries `dirty == false`, even though its content now differs from the just-written file. The status line reports “saved”, autosave skips the tab, and closing the application leaves the newer content on disk rather than the content visible in the editor. Redo has the same class of stale-state problem.

**Required correction:** undo history must represent editable document state, not persistence state. Either remove `dirty` from snapshots or explicitly recompute/set it after every undo/redo relative to a saved revision/content identity. Prefer a saved revision identity over comparing/serializing the whole document. Add regression tests for edit → save → undo and edit → save → undo → redo, asserting both visible content and dirty/autosave behavior.

## P0 — Closing an individual dirty tab discards unsaved work

**Evidence:** the `file.close` command directly calls `Tabs::close_active` (`src/shell/commands.rs:145-152`), and `Tabs::close` removes the tab without saving, returning an error, or asking for confirmation (`src/tabs.rs:224-241`). Autosave is delayed, so closing immediately after an edit is a normal way to hit this path.

**Failure sequence:** type into a note and press Ctrl+W before the idle autosave fires. The only in-memory copy and its undo stack are dropped. The window-close save path cannot help because the tab no longer exists.

**Required correction:** make tab close an explicit fallible policy operation. For a path-backed dirty note, save successfully before removal or keep the tab open and present a visible error. If pathless notes are possible, require a Save As/discard decision. Ensure tab-strip close clicks and Ctrl+W use the same path. Add tests proving a dirty tab is not removed when persistence fails.

## P0 — Application close exits even when persistence fails

**Evidence:** `WindowEvent::CloseRequested` calls `shell.save_all()` and immediately exits (`src/main.rs:114-123`). `Shell::save_all` only prints failures to stderr and returns nothing (`src/shell/mod.rs:1026-1030`). In the GUI, stderr is not a usable recovery surface, and the process exits with dirty documents still only in memory.

**Failure sequence:** make the note unwritable (permissions, disconnected drive, full disk), edit, then close the window. Save fails, a message may be written to an invisible console, and the application exits anyway.

**Required correction:** propagate save failures to the close-request handler, cancel closing while any dirty tab failed, and show an in-app error with retry/cancel and an explicit discard route. Do not clear dirty state on failure. Cover the close decision with a pure/unit-testable policy and an integration test using an unwritable target.

## P1 — Caret movement and scrolling invalidate the full document layout

**Evidence:** `Tabs` uses one `revision` for content, caret, focus, and viewport changes. `touch` bumps it for every motion, even a no-op at a boundary (`src/tabs.rs:316-324`), and `set_editor_scroll` bumps it for wheel movement (`src/tabs.rs:95-102`). `Shell::current_layout` keys the expensive full-document layout cache by that same revision (`src/shell/mod.rs:1239-1268`). The frame loop sees the revision change and replaces the tab strip, breadcrumb, topics, editor, status line, and sidenote components (`src/shell/mod.rs:865-891`, `src/shell/mod.rs:1583-1753`). That rebuild also walks the document for outline/breadcrumb and word count (`src/shell/mod.rs:1477-1484`, `src/shell/mod.rs:1721`).

**Impact:** every `h`/`l` repeat and every wheel tick can reshape the entire note, relayout all math, relayout sidenotes, rebuild unrelated component snapshots, and redraw their layers. Holding a motion at the edge still bumps the revision. This is exactly the sort of input hot path that will spike CPU as notes grow.

**Required correction:** split state identities at least into content/layout revision, caret/focus revision, and viewport/scroll revision. Cache `DocLayout` only by content-affecting revision plus width/theme/font inputs. Update caret and scroll on the existing editor/sidenote components without replacing unrelated regions. Make mutation methods report whether state actually changed so boundary no-ops do not invalidate anything. Add instrumentation tests asserting that caret movement and scrolling neither call document layout nor dirty tab/breadcrumb/topics layers.

## P1 — Every edit clones and compares the entire document, including every keystroke inside a transaction

**Evidence:** `Tabs::edit` clones the active `Document` before invoking every mutation and then performs full body/note equality checks (`src/tabs.rs:261-280`). The clone is unconditional even while `transaction` already holds the undo snapshot, so an insert session still clones the full note on every typed character. Many commands that can be no-ops also travel through this path and still bump the global revision.

**Impact:** editing cost grows with total document size rather than the local edit. Large math trees and sidenote bodies are deep-cloned at keyboard-repeat rate, then traversed again for equality, layout, outline, and word count.

**Required correction:** make document mutations return a changed/not-changed result (or advance a model revision only when they mutate). Capture one undo snapshot at transaction start and do not clone per edit while the transaction is active. Outside a transaction, take a snapshot only for an operation that actually changes state, using a mutation protocol that does not require a second full-document equality walk. Add a test-only clone/layout counter or benchmark for a long insert session.

## P1 — Capture mode implements the opposite mixed-panel transition

**Evidence:** the command comment says “open if any panel is closed, close all of them if every panel is already open,” but the implementation computes `any_open` and assigns every panel to `!any_open` (`src/shell/commands.rs:208-221`).

**Failure sequence:** start with one panel open and another closed, then run “Capture mode” from the palette or Ctrl+Shift+C. Because at least one panel is open, the command closes all panels. The documented/expected behavior is to restore all panels whenever the state is mixed.

**Required correction:** derive `all_open`, then set every panel to `!all_open`. Add table-driven tests for all-open, all-closed, and mixed states so the palette command and shortcut cannot regress independently.

## P2 — Finder search does synchronous full-vault I/O and parsing on every character

**Evidence:** every query change calls `rerank_finder` on the UI thread (`src/shell/input.rs:1597-1609`, `src/shell/input.rs:1664-1670`). `search::text_rows` reads every file and reparses it into a complete document for each query (`src/search.rs:125-133`) before fuzzy matching and sorting. `Vault::files` also recursively walks the filesystem afresh for each query (`src/vault.rs:76-80`, `src/vault.rs:188-214`).

**Impact:** the implementation assumes a small vault, but the cost is unbounded and directly blocks typing/rendering. Slow disks, network-backed vaults, many files, or larger notes will produce visible input stalls. The work repeats even though file contents do not change between adjacent query characters.

**Required correction:** build one searchable snapshot/index when the finder opens (or when vault/document revisions change), reuse parsed flat text for each query, and perform filesystem refresh separately from ranking. If index construction can exceed one frame, move it off the UI thread and publish results by generation so stale searches cannot replace newer ones. Add a benchmark with a realistically large vault and an assertion that changing only the query performs no file reads/parses.

## P2 — Sidenote layout is recomputed instead of cached and can run twice for one caret change

**Evidence:** `stacked_notes` clones every note body and calls `layout_blocks` for every anchored note each time it runs (`src/shell/mod.rs:1491-1545`). `rebuild_views` always invokes it through `sidenote_notes` (`src/shell/mod.rs:1745-1753`). When a note is focused and its caret moves, `ensure_caret_visible` first calls `focused_note_band`, which calls `stacked_notes` once (`src/shell/mod.rs:1281-1335`), and the later margin rebuild calls it again.

**Impact:** note editing can lay out all sidenotes twice per key/motion, on top of the main document relayout caused by the shared revision. Unchanged note bodies are cloned and reshaped repeatedly.

**Required correction:** cache note layouts by note-content revision, margin width/scale, and theme/font inputs; cache the resulting stack placement by main-layout anchor positions. Compute the stack once per rebuild and share it between caret-following, hit testing, and the margin component. Add a counter-based test showing one note-caret motion does not reshape unchanged notes.

## Suggested implementation order

1. Separate persistence state from undo snapshots and fix save/close failure propagation; these are data-loss paths.
2. Split revisions and stop caret/scroll changes from invalidating content layout.
3. Remove per-keystroke document cloning, using the new content revision/change result.
4. Fix capture mode and add its small state-table test.
5. Cache sidenote layout/placement, then index finder content away from the query hot path.

After each change, follow the repository requirements: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, read the diff, and commit the change separately.
